本文深入解析了DRM PLANE的工作原理和意义，它接收framebuffer数据，进行图像剪裁、缩放和旋转，初始化时通过drm_universal_plane_init()设置。PLANE作为图层管理，增强系统灵活性，提高性能，支持多图层叠加，由GPU处理基本图像处理，使GPU更专注于图形渲染。

0. 引言

DRM PLANE 从 drm_framebuffer 接收数据，构造送显图像的雏形，完成图像的剪裁和缩放后发送到&drm_crtc。
除此之外，还通过 drm_plane_state 来提供图像旋转功能。
KMS 驱动通过调用 drm_universal_plane_init()初始化 DRM PLANE。每个 CRTC 需要定义一个 primary plane 以及可选的 overlay plane、cursor plane。

kernel 代码通过一个枚举类型的数据结构定义了 plane 类型。

enum drm_plane_type {
            
	  DRM_PLANE_TYPE_OVERLAY,
	  DRM_PLANE_TYPE_PRIMARY,
	  DRM_PLANE_TYPE_CURSOR,
};

2016 年 9 月 21 日，由 Daniel Vetter 将 drm_plane.c 代码提交到了内核 4.8.0 rc2 版本中。在此之前，plane 相关的公用代码位于 drm_crtc.c 中。

1. PLANE 的工作原理和意义

下面的靶盘由 5 张图片组成，分别在不同的位置。最终形成了一个五种颜色画面的效果。这是图片处理中所谓的图层概念。

同样，在图显系统里的 plane 也可以理解成图层，我们视觉上看到的图像，可以由多个图层叠加而成，这些图层的数据来自不同的内存空间，最后由图显处理器合成并统一输出到显示屏。

以下为多图层叠加示意图：

  • 图层 1
    primary plane 提供背景图案
  • 图层 2
    overlay plane 提供企鹅图案
  • 图层 3
    cursor plane 提供光标图案

每个图层之间可以拥有不同的属性，例如：
exynos 通过数据结构 exynos_drm_plane_config 来表示不同的 plane 属性

struct exynos_drm_plane_config {
            
	  unsigned int zpos;
	  enum drm_plane_type type;
	  const uint32_t *pixel_formats;
	  unsigned int num_pixel_formats;
	  unsigned int capabilities;
};

每个图层的数据均来自于 framebuffer，在不同的 fb 中存放不同的图显数据，针对数据源进行相关操作以实现图像的剪裁、缩放、叠加等等。

剪裁通过改变由 framebuffer 送过来的图显数据 W/H 值来实现；

缩放通过改变 plane 和 crtc 定义的 W/H 来实现；

多图层叠加通过指定 plane 中图显数据在 crtc 中的位置

PLANE 存在的意义主要有两点：

  • 增强系统灵活性
    对于桌面系统而言，显示器背景图案和鼠标光标通常是基本的显示元素，并且一直存在直到系统关机。因此，对于这种变化不是很频繁的基本图显输出，可以由通用 plane 来实现。而那些频繁变化的图显输出，交由专用的 plane 来实现。

  • 提高系统性能
    由于 plane 具备图像缩放、剪裁、多图层叠加等功能，因此，可以让 GPU 来将更多的精力放在图形渲染上，这种基本的图像处理交由 plane 实现。

2. PLANE 的初始化和功能

在 plane 初始化之前，各 SoC 厂商需要例化一个类似于 exynos_drm_plane_config 这样的数据结构，用于描述各个图册的属性、plane 支持的像图像格式等，按照前文的描述，exynos 也是支持 3 各图层的，可以实现 3 帧图像的叠加。

static const struct exynos_drm_plane_config
plane_configs[MIXER_WIN_NR] = {
            
		{
            
			.zpos = 0,
			.type = DRM_PLANE_TYPE_PRIMARY,
			.pixel_formats = mixer_formats,
			.num_pixel_formats = ARRAY_SIZE(mixer_formats),
			.capabilities = EXYNOS_DRM_PLANE_CAP_DOUBLE |
					EXYNOS_DRM_PLANE_CAP_ZPOS,
		},
		{
            
			.zpos = 1,
			.type = DRM_PLANE_TYPE_CURSOR,
			.pixel_formats = mixer_formats,
			.num_pixel_formats = ARRAY_SIZE(mixer_formats),
			.capabilities = EXYNOS_DRM_PLANE_CAP_DOUBLE |
					EXYNOS_DRM_PLANE_CAP_ZPOS,
		},
		{
            
			.zpos = 2,
			.type = DRM_PLANE_TYPE_OVERLAY,
			.pixel_formats = vp_formats,
			.num_pixel_formats = ARRAY_SIZE(vp_formats),
			.capabilities = EXYNOS_DRM_PLANE_CAP_SCALE |
					EXYNOS_DRM_PLANE_CAP_ZPOS |
					EXYNOS_DRM_PLANE_CAP_TILE,
		},
};
