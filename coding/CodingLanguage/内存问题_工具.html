1.1.1. What Can It Detect?
错误行为 简介
global buffer overflow 全局内存访问越界
heap buffer overflow 堆内存访问越界

github.com
initialization order bugs 全局变量初始化顺序异常

全局变量初始化间存在依赖，导致实际运行时因初始化顺序问题导致的初始值异常
memory leaks 内存泄漏

在程序正常退出时输出报告
stack buffer overflow 栈内存访问越界
use after free 访问已经释放的内存，在释放内存后仍然尝试访问此内存

AddressSanitizerExampleUseAfterFree · google/sanitizers Wiki
use after return 访问生命周期结束的对象

在函数退出后尝试访问函数内声明的局部变量
user after scope 访问生命周期结束的对象

在"{}"包起来的代码块外访问代码块内声明的局部变量

1.1.2. 工作原理（how）

基本原理： 给内存建立档案----------影子内存

1、编译期间，~~插桩（自然）

插桩1: 内存分配时

在编译时，ASan会替换malloc/free接口

                在程序申请内存时，ASan会额外分配一部分内存来标识该内存的状态

插桩2: 解引用时（在每一处读取或写入内存的汇编指令之前，插入一段检查逻辑）

当你写下 `*ptr = 10;` 时，

// 编译器自动插入的检查逻辑
byte *shadow_addr = mem_to_shadow(ptr);
if (*shadow_addr != 0) {
    report_error(ptr); // 踩雷了，立即报警并打印调用栈
}
// 原始操作
*ptr = 10;

2、运行时，~~影子内存（自然）

在程序使用内存时，ASan会额外进行判断，确认该内存是否可以被访问，并在访问异常时输出错误信息

详细的工作原理有兴趣可以参考官方文档：https://github.com/google/sanitizers/wiki/AddressSanitizerAlgorithm

补充：~~影子内存 (Shadow Memory) 的映射：

主内存（Main Memory）每 **8 字节**的状态，映射到影子内存的 **1 字节**中。

- 如果这 8 字节都是可读写的，影子内存的值就是 `0`。

- 如果只有前 3 字节能读，值就是 `3`。

- 如果是“有毒”的红区或已释放内存，值就是**负数**。

3、运行时，隔离区：

对付最头疼的悬空指针 (Dangling Pointer)，ASan 引入了“隔离区”。 当你 delete 一个对象时，ASan 不会立刻把内存还给系统，而是把它扔进一个“重症监护室”暂时锁定。如果有悬空指针尝试访问这块“已死”的内存，ASan 会立刻抓住现行，而不是让系统把这块内存分给别人导致数据被莫名修改。

当你 free 掉它，ASan 不会立刻把内存还给 OS，而是把它标记为“隔离状态 (Quarantine)”，防止悬空指针立即复用。

1.1.3. ASan 监控的“函数名单”

除了 malloc 和 new，ASan 还会拦截一系列经典的“高危” C 库函数，确保它们在操作内存时不会越界：

函数类别 被拦截/保护的函数示例
内存分配 malloc, free, calloc, realloc, valloc, posix_memalign
C++ 算子 operator new, operator delete, operator new[]
字符串/内存操作 memcpy, memmove, memset, strcpy, strlen, strcat

1.1.4. 命令：

window下AddressSanitizer没能搞定，主要linux下，编译以及运行命令：

g++  -fsanitize=address -O0 -fno-omit-frame-pointer -g -o  main main.cpp &&  ./main

注意:g++(c++语言)不是gcc (c语言), 不能用错!!!!

遇到报错: Asan runtime does not come first in initial library list; you should either link runtime to your application or manually preload it with LD_PRELOAD

解决方法: mv /etc/ld.so.preload /etc/ld.so.preload.bak rm -rf /etc/ld.so.preload

Ilvm-symbolizer 符号化工具属于 Ilvm包,Ubuntu 下具体的安装方法可以参考 LLVM Debian/Ubuntu nightly packages.

1.2. 内存泄漏

C++造成内存泄漏的原因汇总： https://blog.csdn.net/qq_18824491/article/details/78902636?utm_medium=distribute.pc_relevant.none-task-blog-2~default~baidujs_baidulandingword~default-0.no_search_link&spm=1001.2101.3001.4242.1&utm_relevant_index=3

对于C++的内存泄漏，总结一句话：就是new出来的内存没有通过delete合理的释放掉！！！！！！！！！ ------->在函数体内，1、不用new，创建对象，系统自动回收内存 2、new对象（返回指针），系统不会回收，需要手动

比喻：1、申请内存就像不停打开网页 2、没有及时关闭网页 3、new 网页，谁new应该谁关 4、如果不关网页，系统掉电重启，内存会全部清掉
